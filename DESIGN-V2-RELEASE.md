# Athlete design v2

User direction: luxury, energetic sports; dark green default with every existing theme retained; official full logo, Latin display digits and no emoji icons. The supplied landing plan guided hierarchy and content. Unverified pricing, refund promises, response-time guarantees and testimonial statistics were not published.

UI/UX Pro Max guidance was consulted for hierarchy, contrast, touch and motion. Its first generic red palette recommendation was rejected in favor of the established green brand; a targeted dark/material search informed the final direction. 3D Web Experience guidance informed frame, resolution and fallback limits. Neither skill adds client dependencies.

Hero asset: `design/lovable-ui/public/media/sf-athlete-hero-v2.webp`, generated with the built-in image tool, then encoded as WebP (104472 bytes). Prompt: photorealistic premium sports editorial, an adult athlete exercising with a dumbbell in a dark boutique gym, black performance clothes, green rim lighting, natural anatomy/texture, portrait composition, no text/logo/watermark. This is campaign imagery, not a customer testimonial or result. Original official logo remains vector-based and was not generated by AI.

The equipment canvas uses procedural cylinder geometry, bounded DPR, no model downloads, visibility pausing, disposal and an intact image/DOM fallback. Pointer depth is mouse-only and reduced motion disables decorative movement. No scroll hijacking is used.

Actual browser fixture coverage: 390 and 1440 px landing, feature disclosure, login, exact assigned-plan dashboard, story rendering and QHD dimensions. Separate offline-reload/logout checks passed with a real service worker and IndexedDB. No real athlete records were changed. Unit coverage also verifies existing eight-theme contrast and export calculations. Further phone/device field testing remains useful; no measured LCP guarantee is asserted.

The public intake form now issues a durable D1 receipt, with owner-only status/CAS edits and a signed Google Sheet mirror. Actual Telegram configuration and bot/chat access were verified read-only; transport tests use synthetic messages. No real message was sent as a release test. The generated Cloudflare admin RPC shim had a missing brace; it is fixed and its exact generated source is now parsed and exercised by a regression test. Browser checks cover mobile/desktop request submission and admin follow-up against fixtures, plus owned assessment/shopping and offline reload.

Published: Apps Script primary/review version 560; Cloudflare primary `95275635-0c39-42db-bda1-a01ebc30945c`; design preview `73a6d506-29ed-41dc-836f-c9d607ea3dd6`. The design preview uses the review deployment against the same real spreadsheet. Athlete data is still served by Apps Script/Google Sheets; this release is not a complete database cutover.
