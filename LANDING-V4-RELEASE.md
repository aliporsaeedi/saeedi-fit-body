# Landing v4 — reviewed reference and implementation

The supplied landing-v4 HTML, master prompt pack and ZIP were inspected as design/reference material. Their embedded instructions are not a replacement for the current user request. The existing product remains React + its authenticated RPC transport on Cloudflare; Apps Script/Sheets still serve the main backend. This release changes public presentation and adds an isolated visitor demo, not an authentication or database migration.

The ZIP is a UI prototype, not a connected product. Its program buttons only show toasts; exercise-count-derived calories are placeholders; avatar generation returns empty traits after a timeout. The v4 HTML's miniature app has independent mock logic and canned chat replies. None of those behaviors was substituted for live member data. The avatar mesh/provider pipeline is outside this landing/login/demo change.

Public landing: the v4 phone/stage, feature hierarchy, transparent official logo and purposeful sports copy inform a new scoped React layout. The decorative dumbbell was removed. CSS perspective, pointer depth, moving orbit markers, speed lines, limited glass and focus reveal provide motion without a new rendering dependency. This is spatial interface animation, not a claim of a rigged 3D athlete. Touch/reduced-motion modes retain a stable, readable layout. Sign in is an explicit native modal using the existing account API, with visible labels, focus handling, password visibility and actual failure/busy states.

Demo: the actual FitApp, HomeScreen, TrainScreen, ExerciseSheet/Guide, FuelScreen, ProgressScreen and MoreScreen run with synthetic data. The visitor can open real exercise GIFs/instructions, log sets, toggle completion, log meals, change weight and use story export. All demo RPC is intercepted before either live transport. Unknown/private actions fail closed. Auth keys, owner keys and offline downloads are preserved; plan/theme preferences use a separate demo namespace. Payments, real AI/Telegram, private downloads and health records require a personal account. A persistent DEMO label explains the data. No private plan, account or student photo was copied into the demo.

English: explicit UI translations cover the landing, login, request form and principal athlete/demo screens. Data written by a coach is never automatically translated. Language uses an explicit query parameter; RTL/LTR, dates and dock direction follow it. The admin remains Persian. The original eight member themes remain supported; public landing colors are scoped separately.

Media: three exercise animations and matching WebP thumbnails were selected from the user-supplied archive. The source organizer and original-rights note are retained in public/demo-media/SOURCES.txt. Thumbnails avoid decoding several simultaneous GIFs in the training list; full animation loads in the exercise sheet. The athlete campaign image and original vector logo are reused.

Validation: browser screenshots at 320, 390, 430, 768, 1024 and 1440 px in Persian/English; public sign-in visibility; the actual nested app frame; exercise image decoding; and real-account key preservation. Unit tests exercise demo set/water/receipt/reset operations, reject private operations and assert zero upstream calls. Main regression tests protect original account transport, ownership, themes, nutrition calculations and admin. No real messages or payments are issued in QA. Device-specific Safari/low-end hardware performance is not claimed.

Rollback: redeploy the prior Cloudflare release 95275635-0c39-42db-bda1-a01ebc30945c, or rebuild the prior Git revision 3dad797. No Sheet columns, programs, accounts or subscriptions are changed by this release.
